TOPIK 1

Teori Dasar & Skalabilitas

Centralized vs Decentralized vs Distributed, 3 Skalabilitas, 6 Transparansi.

Arsitektur:
  • Centralized: Single point of control & failure.
  • Decentralized: Tidak ada kontrol tunggal, node sejajar (P2P).
  • Distributed: Kumpulan komputer independen yang tampak sebagai 1 sistem tunggal yang koheren.
3 Dimensi Skalabilitas: 1. Size (Ukuran pengguna) | 2. Geographical (Latensi lokasi) | 3. Administrative (Lintas organisasi).
Transparansi Kunci: Access, Location, Relocation/Migration, Replication, Concurrency, Failure.
TOPIK 2

Gaya Arsitektur Komunikasi

RESTful Architecture vs Publish-Subscribe & Decoupling.

RESTful Architecture:
  • Resource-Oriented: Diakses via URI unik (misal `/api/users/12`).
  • Stateless: Server tidak menyimpan state sesi client. Setiap request membawa context lengkap.
  • Standard Verbs: GET, POST, PUT, DELETE.
Publish-Subscribe (Pub/Sub):

Komunikasi berbasis Event via Broker.

  • Space Decoupling: Publisher & Subscriber tidak perlu tahu IP/identitas lawan.
  • Time Decoupling: Publisher & Subscriber tidak wajib online bersamaan.
TOPIK 3

Proses & Virtualisasi

Process vs Thread, Container, Namespaces & cgroups.

Process vs Thread:
  • Proses: Memiliki memori terisolasi. Context switch berat.
  • Thread: Berbagi memori dalam 1 proses. Context switch sangat ringan & cepat.
Containerization (OS-Level Virtualization):

Berbagi Host Kernel OS (lebih ringan dibanding VM full OS).

  • Namespaces: Mengisolasi tampilan resource (PID, Network, Mount).
  • cgroups: Membatasi kuota penggunaan hardware (CPU, RAM, Disk I/O).
TOPIK 4

Komunikasi Remote (RPC)

RPC, Stubs, Marshaling & Unmarshaling.

Prinsip RPC:

Memberikan transparansi lokasi (*location transparency*) agar pemanggilan fungsi jarak jauh terasa seperti fungsi lokal biasa.

Alur RPC & Stub:
  1. Client Stub: Mengemas nama fungsi & argumen menjadi bentuk biner/pesan (Marshaling).
  2. Network Transport: Mengirim paket via socket.
  3. Server Stub: Pembongkaran pesan biner menjadi parameter asli (Unmarshaling) & mengeksekusi fungsi server.
TOPIK 5

Sinkronisasi Jam Logis

Lamport Logical Clock vs Vector Clock.

Lamport Clock:

Event lokal: $L_i = L_i + 1$. Pesan kirim bawa $t = L_i$. Terima pesan: $L_j = \max(L_j, t) + 1$.

⚠️ Kelemahan: $L(a) < L(b)$ TIDAK menjamin $a \to b$ (bisa jadi konkuren).

Vector Clock (Mendeteksi Konkurensi):

Setiap node menyimpan array $V_i[1..N]$. Terima: $V_j[k] = \max(V_j[k], V_{msg}[k])$, lalu $V_j[j]++$.

Kondisi Konkuren: Event $a \parallel b \iff V(a) \not\le V(b) \land V(b) \not\le V(a)$.

TOPIK 6

Penamaan & Chord DHT

Identitas, Consistent Hashing & Finger Table Chord.

Name vs Address vs Identifier:
  • Name: Human-readable (misal `google.com`).
  • Address: Lokasi titik akses entitas (IP Address).
  • Identifier: Unik persis 1:1, tak pernah diubah atau digunakan ulang.
Chord DHT ($2^m$ Ring):

Key $k$ disimpan di node pertama $\ge k$ yaitu $\text{successor}(k)$.

Finger[i] = successor((n + 2^(i-1)) mod 2^m)

Kompleksitas pencarian lookup: $O(\log N)$ hops.

TOPIK 7

Model Konsistensi Replikasi (Data-Centric)

Sequential Consistency vs Causal Consistency (Perbandingan Analisis Trace).

1. Sequential Consistency (Sekuensial)

Seluruh operasi Read & Write dari semua node harus tampak berjalan dalam satu urutan sekuensial global yang sama persis di seluruh proses, dan sesuai dengan urutan program lokal masing-masing node.

VALID Contoh Trace Sekuensial:

P1: W(x)a

P2: W(x)b

P3: R(x)b R(x)a (Urutan global: W(x)b -> R(x)b -> W(x)a -> R(x)a)

P4: R(x)b R(x)a (Semua node melihat b DULU baru a!)

2. Causal Consistency (Kausal)

Hanya operasi Write yang terhubung secara kausal ($a \to b$) yang wajib dilihat dalam urutan yang sama oleh semua node. Write yang konkuren boleh dilihat dalam urutan berbeda.

VALID Kausal tapi INVALID Sekuensial:

P1: W(x)a (Konkuren dengan W(x)b)

P2: W(x)b (Konkuren dengan W(x)a)

P3: R(x)a R(x)b

P4: R(x)b R(x)a (Boleh beda urutan karena W(a) & W(b) konkuren!)
